     INPUT DATA                                                 EXPECTED RESULT
 
- VÍ DỤ:
     INPUT 25               Math.sqrt(25)           ----------> expected result: 5
                            Java, C#, Python 
     -----------------------------------------------------------------------------> TEST CASE

     QA/QC/TESTER
     INPUT USER/PASS ------------> MÀN HÌNH LOGIN ------------> EXPECTED RESULT 
           ĐÚNG / ĐÚNG                                          MỜI VÀO, LOGIN THÀNH CÔNG
           ĐÚNG / SAI                    "                      CHỬI SAI PASS, KO CHO VÀO

           ĐÚNG / SAI                    "                      CHỬI SAI, ++ SỐ LẦN SAI
                                                                SAI ĐỦ 5 LẦN LOCK ACCOUNT
           ...

    THỰC TẾ KHI ĐƯA VÀO VÀ CHẠY VỚI BỘ TEST CASE, BỘ DATA Ở TRÊN => GỌI LÀ TEST RUN 
    TEST RUN: RUN BỘ TEST DATA VÀ SO SÁNH VỚI EXPECTED RESULT COI ACTUAL RESULT - APP TRẢ VỀ GÌ?
                                   ACTUAL RESULT == EXPECTED RESULT -> PASSED
                                   ACTUAL RESULT != EXPECTED RESULT -> FAILED, BUG!!!

    RUN: KHI CHẠY CĂN BẬC 2 CỦA 25 HÀM SQRT KO TRẢ VỀ 5 -> FAILED
    RUN: KHI CHẠY CĂN BẬC 2 CỦA 25 HÀM SQRT TRẢ VỀ 5 -> PASSED
    RUN: KHI NHẬP SAI PASS 5 LẦN, KO CẢNH BÁO LOCK ACCOUNT -> FAILED
    RUN: KHI NHẬP SAI PASS 5 LẦN, CÓ CẢNH BÁO LOCK ACCOUNT -> PASSED
    RUN: KHI NHẬP ĐÚNG Ở LẦN 6, PHẢI BÁO ACCOUNT ĐÃ BỊ LOCK -> PASSED

CÂU 3 - THIẾT KẾ TEST CASE ĐỂ TEST CHỨC NĂNG, TEST MÀN HÌNH, FUNCTIONAL TESTING
* CÓ NHIỀU KĨ THUẬT CÓ THỂ ÁP DỤNG ĐỂ THIẾT KẾ SỐ LƯỢNG TEST CASE BAO SÂN CÁC TÌNH HUỐNG NHẬP LIỆU TRÊN MÀN HÌNH
* 3 KĨ THUẬT HAY DÙNG: EQUIVALENCE PARTITIONING - EP, BOUNDARY VALUE ANALYSIS (BVA), DECISION TABLE 
- EP: CHIA MIỀN DỮ LIỆU NHẬP LIỆU VÀO Ô NHẬP THÀNH 2 VÙNG: VALID VÀ !VALID, HỢP LỆ VÀ KO HỢP LỆ
- BVA: KHI MIỀN DỮ LIỆU NHẬP CÓ MIN-MAX, RANGE - KHOẢNG, 
  CHÚ Ý GIÁ TRỊ MIN-1, MAX+1 NÓ BẮT ĐẦU LÀ NƠI THAY ĐỔI CÁCH TÍNH TOÁN XỬ LÝ CỦA APP, CẦN ĐC TEST
- DECISION TABLE: LÀ BẢNG 2 CHIỀU HÀNG CỘT; GHI RA CÁC TỔ HỢP NHẬP LIỆU CỦA CÁC Ô NHẬP LIỆU
                  MỖI TỔ HỢP CHÍNH LÀ TEST CASE

                          MỖI TEST CASE THEO CHIỀU DỌC 
                          LÀ TỔ HỢP TRUE/FALSE CỦA CÁC Ô NHẬP Ở CỘT ĐẦU TIÊN

  CỘT 1                  | TEST CASE 1| TEST CASE 2 | ...
  (CỘT ĐẦU VÀO)                TRUE        FALSE
  MÃ SỐ       HỢP-LỆ?          YES          NO
  TÊN-SV      HỢP-LỆ?
  EMAIL       HỢP-LỆ?           NO
  SEARCH KW   HỢP-LỆ?           -           -

  -----------------------------------------------------
  TEST DATA              GHI RA VALUE CỤ
                         THỂ CÁC Ô NHẬP
                         CỦA 1 TC THEO CHIỀU
                         DỌC
  -----------------------------------------------------
  EXPECTED RESULT        VỚI BỘ TỔ HỢP DATA THEO
                         CHIỀU DỌC CỦA TỪNG TC
                         THÌ APP CÓ KQ LÀ THẾ NÀO
                         XỬ LÝ THẾ NÀO
